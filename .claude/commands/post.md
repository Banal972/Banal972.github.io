# 블로그 글 작성

Obsidian vault 의 기술 초안을 **Banal.log 의 문체**로 다시 써서 `src/content/blog/` 에 발행합니다.

초안 위치: `/Users/kimjiyu/Documents/Obsidian Vault/기술 블로그/`
인덱스: 같은 폴더의 `00. 인덱스.md` (주제별 목록 + 발행 전 체크리스트)

인자로 초안 파일명이나 주제가 넘어오면 그 글을, 없으면 인덱스에서 아직 발행되지 않은 것 중
하나를 골라서 작업합니다: $ARGUMENTS

---

## 1. 먼저 읽을 것

- 대상 초안 전문
- `00. 인덱스.md` 의 "발행 전 공통 체크" 섹션
- 기존 글 2~3편 (`src/content/blog/cut-styled-component.md`, `use-modal.md`, `ios26-flutter.md`)
  — 문체 감각을 매번 다시 잡기 위함

## 2. 문체

초안은 **기술 보고서** 톤입니다. 블로그는 그것보다 **말을 걸듯이** 씁니다.

- **합니다체**가 기본입니다.
- **1인칭을 씁니다.** "저는 ~", "저 역시 ~", "제가 자주 쓰는 방법은 ~".
  겪은 사람이 쓰는 글이라는 게 드러나야 합니다.
- **소제목은 질문형을 즐겨 씁니다.** "왜 개발 환경에서만 Proxy가 동작할까?",
  "그러면 아예 개발을 못해?", "언제 배포?" 처럼요.
- **도입 2~4줄로 상황을 깔고 시작합니다.** 바로 원인부터 들어가지 않습니다.
  "개발을 하다 보면 ~ 하는 경우를 자주 보게 됩니다" 같이 공감을 먼저 얻습니다.
- **문단은 짧게, 빈 줄로 자주 끊습니다.** 세 줄 넘어가면 끊을 곳을 찾습니다.
- **끝에는 소감이 붙습니다.** 정리만 하고 끝내지 않고 한두 줄 개인적인 말을 답니다.
- 과장된 감탄사나 이모지는 쓰지 않습니다. 담백한 구어체입니다.

**하지 말 것**
- 초안 문장을 그대로 복사해 붙이기 (톤이 튑니다)
- "결론적으로", "요약하자면" 같은 보고서 접속어 남발
- 초안에 없는 내용을 추측으로 채우기 — 사실은 초안이 유일한 근거입니다

## 3. 구조

```
도입 (2~4줄, 어떤 상황에서 뭘 겪었는지)

## 무슨 일이 있었나 / 증상

---

## 왜 그랬을까 (원인)

---

## 어떻게 고쳤나 (해결)

---

## 정리 (배운 것 + 소감)
```

- `##` 이 기본 소제목입니다. 더 잘게 나눌 때만 `###` 를 씁니다.
- 큰 단락 사이에는 `---` 를 넣습니다.
- 초안의 "배운 것" 섹션은 마지막 정리로 녹입니다. 불릿 3~4개가 적당합니다.

## 4. 마크다운 규칙 (이 블로그 특성)

- **줄바꿈은 줄 끝 공백 두 칸.** 문단 안에서 줄을 바꾸고 싶을 때 씁니다.
- **`**볼드**` 는 핵심 용어에, `` `코드` `` 는 식별자·파일명·명령어에** 씁니다.
- **코드블록에 언어를 반드시 지정합니다** (`tsx`, `ts`, `js`, `html`, `bash`).
- **HTML 태그를 본문에 직접 쓸 때는 앞뒤에 빈 줄을 넣습니다.**
  빈 줄이 없으면 CommonMark 가 뒤 문단까지 HTML 블록으로 삼켜서 마크다운이 안 먹습니다.
- 이미지는 `public/assets/img/post/<YYYY-MM-DD-slug>/` 에 두고
  `/assets/img/post/<YYYY-MM-DD-slug>/파일명` 으로 참조합니다.

## 5. frontmatter

```markdown
---
title: "글 제목"
date: YYYY-MM-DD
categories: ["React"]
tags: ["React", "성능 최적화"]
---
```

- **파일명이 곧 URL 입니다.** `src/content/blog/use-modal.md` → `/posts/use-modal/`
  영어 kebab-case 로, 짧고 내용을 드러내게 짓습니다.
- `title` 은 훅이 있어야 합니다. 기존 글의 패턴:
  - `~하는 이유` — "Vite, CRA, Next 등 여러 dev 환경에서 proxy가 되는 이유"
  - `~해보자` — "리액트에서 귀찮았던 모달을 간편하게 만들어보자"
  - 경고형 — "flutter 개발자라면 iOS26으로 업데이트 하는것은 잠시 멈춰주세요"
  - 의문형 — "뭐? Styled-Components가 끝났다고?"
- `categories` 는 기존 값 중에서 고릅니다:
  `React` `Nextjs` `Native` `Expo` `Flutter` `Javascript`
  `Functional-programming` `Design-pattren` `Discover` `Blog` `Books` `Etc`
  주제를 가장 잘 드러내는 하나면 충분합니다.
- `date` 는 오늘 날짜입니다.
- `description` 은 생략합니다 (본문 앞부분에서 자동 생성됩니다).
- 대표 이미지가 있으면 `heroImage` 를 넣고, 없으면 생략합니다
  (카테고리 색 타이포 카드로 자동 대체됩니다).

## 6. 발행 전 마스킹 — 반드시

초안은 실제 업무 기록이라 **공개하면 안 되는 정보가 섞여 있습니다.**

- **도메인, 서버 IP, 포트, 파일 경로, 계정명** → 전부 일반화하거나 플레이스홀더로
- **회사·서비스·프로젝트 실명** → "상품 상세 페이지", "사내 관리자 페이지" 처럼 역할로만
- **크롤러 관련 글** → 대상 사이트를 특정하지 않습니다. 우회 방법이 아니라 원리를 설명하는 글로 프레이밍합니다
- **측정 수치** → 로컬 실측값이면 절대값에 의미를 두지 않도록 문맥을 덧붙입니다

마스킹한 항목은 작업 후 사용자에게 **목록으로 보고합니다.**

## 7. 마무리

1. `npm run build` 로 빌드가 깨지지 않는지 확인합니다.
2. 렌더링된 HTML 에 리터럴 `**` 나 노출된 `<div>` 가 없는지 확인합니다.
3. **초안을 발행 완료로 표시합니다.**
   - 초안 파일 맨 위에 `> 발행: YYYY-MM-DD — /posts/<slug>/` 한 줄을 추가
   - `00. 인덱스.md` 의 해당 항목 줄 끝에 ` ✅ 발행 (YYYY-MM-DD)` 추가
4. 사용자에게 보고: 제목 / URL / 카테고리·태그 / 마스킹한 항목 / 초안 대비 바꾼 것

배포는 `master` 에 푸시하면 자동으로 됩니다. **푸시는 사용자가 확인한 뒤에 합니다.**
