디바이스에서 페이지를 확인하다가 이상한 현상을 발견했습니다.

스크롤이 중간중간 뭉개지고, 초기 로딩도 굉장히 느렸습니다.

그런데 이상하게 데스크톱에서는 멀쩡했고, 개발자 도구에서 모바일 뷰포트와 CPU 스로틀을 걸어도 같은 문제가 잘 재현되지 않았습니다.

원인은 화면에서 거의 눈에 띄지도 않던 블러 스타일이었습니다.

```html
<div
  class="absolute size-[120px] rounded-full bg-brand blur-[120px] [will-change:transform]"
/>
```

지름 120px짜리 원에 `filter: blur(120px)`를 적용해서 빛이 번지는 것처럼 표현한 요소였습니다.

이 블러를 `radial-gradient`로 변경한 뒤 실제 디바이스에서 초기 로딩과 스크롤 성능이 눈에 띄게 좋아졌습니다.

## 원인

처음에는 Motion쪽을 의심했습니다.

페이지에는 계속 움직이는 이미지, 마퀴, 자동 재생 캐러셀처럼 여러 애니메이션이 동작하고 있었습니다.

실제로 프로파일링을 해보면 아무것도 하지 않는 상태에서도 메인 스레드에서 작업이 계속 발생하고 있었습니다.

그래서 `prefers-reduced-motion: reduce`를 적용해서 애니메이션을 거의 전부 멈춰봤습니다.

메인 스레드 작업은 크게 줄었지만, 실제 디바이스에서 느껴지던 초기 로딩 문제는 그대로였습니다.

결국 컴포넌트를 하나씩 제거하면서 확인했고, 블러 요소를 제거했을 때 문제가 바로 사라졌습니다.

### 작은 블러가 왜 무거웠을까?

코드만 보면 지름 120px짜리 작은 원입니다.

```html
<div class="size-[120px] rounded-full bg-brand blur-[120px]" />
```

하지만 `filter: blur()`는 이 120×120px 영역만 처리하는 것이 아닙니다.

블러는 요소 바깥으로 퍼지기 때문에 브라우저는 주변의 더 넓은 영역까지 함께 처리해야 합니다.

`blur()` 값이 커질수록 처리해야 하는 영역도 함께 커질 수 있습니다.

여기에 모바일 디바이스의 높은 DPR도 영향을 줍니다.

예를 들어 DPR이 3이라면 같은 CSS 영역이라도 가로와 세로에 각각 3배 많은 디바이스 픽셀이 사용됩니다. 픽셀 수로 보면 DPR 1보다 약 9배 많습니다.

해당 요소에는 `will-change`도 적용되어 있었습니다.

```css
will-change: transform;
```

`will-change`는 브라우저에게 앞으로 변경될 가능성이 있는 요소라고 알려주는 힌트입니다.

경우에 따라 합성 레이어 최적화에 영향을 줄 수 있지만, 항상 성능을 좋아지게 만드는 속성은 아닙니다.

데스크톱에서는 크게 문제가 없었지만, 실제 모바일 디바이스에서는 큰 블러 영역과 높은 DPR이 겹치면서 렌더링 부담이 커졌던 것으로 보입니다.

정확히 GPU의 어느 단계가 병목이었는지까지 분리해서 측정하지는 못했습니다.

다만 확인한 결과는 명확했습니다.

1. 데스크톱에서는 문제가 재현되지 않았습니다.
2. 개발자 도구의 모바일 에뮬레이션에서도 잘 재현되지 않았습니다.
3. 실제 디바이스에서 블러를 제거하자 문제가 사라졌습니다.

개발자 도구의 모바일 에뮬레이션은 실제 모바일 GPU 환경까지 그대로 재현하는 것은 아니기 때문에 이런 문제는 결국 실기기에서 확인할 필요가 있었습니다.

## 해결

이 블러가 표현하고 있던 것은 단순한 빛 번짐 효과였습니다.

움직이는 것도 아니고, 사용자의 입력에 따라 모양이 변하는 것도 아니었습니다.

그래서 굳이 `filter: blur()`를 사용할 필요가 없다고 판단했습니다.

대신 `radial-gradient`로 비슷한 모양을 만들었습니다.

기존에는 이렇게 원에 직접 블러를 적용했습니다.

```html
<div class="absolute size-[120px] rounded-full bg-brand blur-[120px]" />
```

변경 후에는 `Glow` 컴포넌트 내부에서 그라디언트를 만들도록 했습니다.

```tsx
<Glow
  className="top-[567px] left-[7.19%] size-[120px] text-brand"
  size={120}
  blur={120}
/>
```

실제 그라디언트는 기존 원보다 조금 더 큰 영역으로 만들고 중심 위치를 맞췄습니다.

```tsx
<div
  className="absolute left-1/2 top-1/2"
  style={{
    width: diameter,
    height: diameter,
    marginLeft: -diameter / 2,
    marginTop: -diameter / 2,
    backgroundImage: `radial-gradient(circle, ${ramp}, transparent 70%)`,
  }}
/>
```

이렇게 하면 브라우저가 넓은 영역에 `filter: blur()`를 적용하는 대신, 이미 색상 변화가 정의된 그라디언트를 그리게 됩니다.

### 원본과 밝기 맞추기

처음에는 중심에 원래 색상을 넣고 바깥쪽으로 투명해지는 단순한 그라디언트를 만들었습니다.

그런데 기존 블러보다 중심이 훨씬 밝게 보였습니다.

`filter: blur()`는 작은 원의 색을 주변으로 퍼뜨리기 때문에 중심의 색도 함께 옅어집니다.

반면 `radial-gradient`에 원래 색상을 그대로 사용하면 중심 색상이 너무 진하게 남습니다.

그래서 기존 원의 크기와 `blur` 값을 기준으로 그라디언트 중심의 투명도를 낮춰 비슷한 밝기가 나오도록 조정했습니다.

변경 전 `filter: blur()`와 새로 만든 그라디언트를 같이 렌더링해서 비교했고, 실제 화면에서는 거의 차이를 느끼기 어려운 정도로 맞출 수 있었습니다.

### 가로 스크롤 문제

블러를 그라디언트로 바꾸고 나니 예상하지 못한 문제가 하나 생겼습니다.

일부 페이지에서 가로 스크롤이 생겼습니다.

이유는 `filter: blur()`와 그라디언트의 차이였습니다.

`filter: blur()`는 요소 바깥으로 퍼져 보이더라도 실제 요소의 크기가 커지는 것은 아닙니다.

반면 새로 만든 그라디언트는 큰 크기의 실제 요소를 만들어서 표현하고 있었기 때문에 화면 밖으로 나가면서 문서의 가로 폭까지 넓히고 있었습니다.

전역에 `overflow-x: hidden`을 적용할 수도 있었지만, 다른 레이아웃이나 sticky 요소에 영향을 줄 가능성이 있었습니다.

그래서 글로우 요소만 별도의 컨테이너로 감싸서 잘라냈습니다.

```tsx
<div
  aria-hidden
  className="pointer-events-none absolute inset-0 overflow-hidden"
>
  <Glow ... />
  <Glow ... />
</div>
```

이렇게 하면 섹션 전체의 overflow에는 영향을 주지 않고, 장식용 글로우만 화면 안에서 잘리도록 만들 수 있습니다.

## 결과

`filter: blur()`를 `radial-gradient`로 변경한 뒤 실제 디바이스에서 가장 크게 느껴졌던 문제가 개선됐습니다.

기존에는 페이지 진입 시 초기 로딩이 느리고 스크롤 중 화면이 뭉개지는 현상이 있었지만, 변경 후에는 이런 현상이 눈에 띄게 줄었습니다.

디자인 차이도 거의 없었고, 변경 전후 페이지를 같은 크기로 캡처해서 비교했고, 글로우 주변에서는 육안으로 구분하기 어려운 정도의 차이만 있었습니다.

가로 스크롤도 다시 확인해서 PC와 모바일 모두 발생하지 않는 것을 확인했습니다.

처음에는 여러 애니메이션이 원인이라고 생각했습니다.

실제로 계속 실행되는 애니메이션도 있었고, 이 부분은 별도로 최적화할 필요가 있었습니다.

하지만 이번 모바일 성능 문제의 직접적인 원인은 움직이는 요소가 아니라 정적으로 놓여 있던 `filter: blur()`였습니다.

화면에서 작게 보이는 요소라고 해서 렌더링 비용까지 작은 것은 아니었습니다.

특히 큰 `blur()` 값을 사용하는 장식 요소라면 실제 모바일 디바이스에서도 한 번 확인해볼 필요가 있습니다.

그리고 움직이지 않는 단순한 빛 번짐 효과라면 `filter: blur()` 대신 `radial-gradient`처럼 처음부터 완성된 형태를 그리는 방법이 더 단순하고 적합할 수 있습니다.
